Albert Sans Variable, self-hosted, one file for weights 100 to 900. Seven steps on a 14px root. The scale exists because the performer header once rendered twelve sizes, three of them within half a pixel of each other.
The font path fails silently.
It must be /plugin/refract/assets/fonts/..., absolute, with the /assets/ segment Stash adds. Get it wrong and the theme falls back to system-ui, which looks close enough that v1.10.2 shipped broken. Verify in DevTools Network: 200, not 404.

Six or seven pairs, not twenty.
The scene detail panel measured 20 size and weight pairs in a 338px column. 10.08px alone carried 119 elements across three weights. When one size does six jobs it has stopped being a level and become the default.
Hierarchy is three things at once.
Size and weight and colour together. Muted text at the same size is a level. Three weights at the same size is not. Current adoption of the scale is 301 token uses against 99 literals.

getBoundingClientRect returns the line box, which reserves descender space whether or not the string has a descender. A box-centred label without one reads high.
Albert Sans at 11px: ascent 10, descent 3, cap 8. That asymmetry is the whole cause. Tab labels that measured 0.5px off by the box model were 1.5px high in rendered pixels.
Centre on cap height and let descenders hang.
